# Security checklist — WP-0.5 custom fields (0197, D-222)

Evidence in `supabase/tests/crm_fields_invariants.sql` (CFI) unless named.

| # | Item | Result |
| --- | --- | --- |
| 1 | Entry points check session, role, permission | The registry's calls: reading needs a CRM reader at aal2 (`crm_can_read()`); `admin_crm_field_save`, `_field_archive`, `_field_group_save`, `_field_group_archive` need the CRM's settings action (`crm_can('global.settings')`) and a reason while typed reasons are on (CFI 5). Values go through the existing record calls, which keep their actions (0196). The five calls and the new `admin_crm_companies(text,text,uuid,jsonb)` are executable by `authenticated` only; the old three-argument list is dropped; the 22 helpers are executable by no client role (CFI 1) |
| 2 | No secret in the client | None added |
| 3 | Inputs validated | Zod in `lib/admin/crmFieldActions.ts` (uuids, key pattern, label ≤ 80, description ≤ 500, type and rule enums, ≤ 100 sets) and `lib/admin/crmActions.ts` (custom values ≤ 200 keys by key pattern, conditions by `Conditions`, import columns ≤ 100 of ≤ 10,000 characters); again in the database: reserved keys, a type or an option in use, a field a formula reads and a group in use are refused (CFI 12), and the key pattern, unique options and an existing stage, set and group are checked by `admin_crm_field_save`; every value is checked for its field's type by `app.crm_field_value` and nothing else is stored (CFI 3); conditions are checked against live fields and their operators (`app.crm_conditions_ok`, CFI 8) |
| 4–5 | Rich text, uploads | Not applicable: a large text is plain text, rendered as text |
| 6 | Exports | None added. The consent export reads no custom value |
| 7 | Outbound | None |
| 8 | Credentials | None |
| 9 | Public surfaces | None: the registry and the values are admin-only; the respondent and customer surfaces read neither |
| 10 | AI | Not applicable |
| 11 | Audit and append-only | Every registry change is audited (`crm.field_save`, `crm.field_archive` / `crm.field_unarchive`, `crm.field_group_save`, `crm.field_group_archive` / `crm.field_group_unarchive`) with a reason when typed reasons are on; every field save is a whole version in `app.crm_field_versions`, which no one may change and which goes only with its field — the guard permits referential maintenance (CFI 7, 14); each change to a custom value is a history line of its own (CFI 10); reading the registry is audited (`crm.fields`) and the call is VOLATILE |
| 12 | Caller's permissions | Each call runs with the caller's role and set. A field hidden from the caller's set is absent from every reader — the record, the lists, the history, the segment filters and the registry — and refused as unknown by every writer; a read-only one is refused as read only; the Admin set and the system's own jobs see and write every field (CFI 5). A reference names only an organization the caller can see (0196) |
| 13 | No message bodies, tokens or personal data in logs | Audit details carry field keys, labels, types and set ids; a contact save logs the custom keys it changed, not their values; an import's audit row carries counts only (rows, inserted, updated, rejected, warnings). Custom values reach the history, which is the record's own changelog (0194), not a log |
| 14 | Dependency audit | No dependency added |
| 15 | db lint, advisors | `supabase db lint --local --level warning` exit 0, warnings only: in the functions 0197 adds or changes, only the codebase's usual one (an array or jsonb variable initialised from a text literal). `app.crm_date_text` builds its date with `make_date` rather than a cast, which would read the session's DateStyle, so it is truly immutable. On hosted after 0197 (D-222): the security advisors add exactly the five registry calls (`authenticated`, gated inside) and the three tables (RLS without policy) to their deliberate classes, the anon class is unchanged at 31; the performance advisors find no unindexed foreign key on the new tables |
| 16 | Firewall | No function a CRM call reaches reads an answer table (`crm_access_invariants` seq 11 covers the new calls); `growth_firewall_invariants` and `respondent_invariants` pass |
| 17 | No dynamic SQL from admin input | A formula is compiled once into postfix form (`app.crm_formula_compile`) and evaluated by `app.crm_formula_eval` over numbers only; no field key, label or formula is ever spliced into SQL. Filters compare jsonb values through fixed operators (`app.crm_custom_match`). Adding a field creates no index or column: one GIN index per table serves every field (CLAUDE.md invariant 8) |
| 18 | No reader hands out a whole row | Every function that turns a company or contact row into JSON goes through `crm_company_json` / `crm_contact_json`, which apply the registry; a structural check fails on any function serialising a whole row (CFI 13) |
| 19 | Defaults change nothing | No field exists until an admin adds one; the two rules are unlimited; every value column starts empty (CFI 1) |
